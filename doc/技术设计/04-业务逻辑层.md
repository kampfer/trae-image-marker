# 业务逻辑层设计

## 整体架构

业务逻辑层采用 Redux Toolkit 进行状态管理，实现状态的集中化管理和可预测性。整体架构分为以下几个核心 Slice：

```text
src/store/
├── index.ts                    # Store 配置中心
├── middleware/                 # 中间件
│   └── reduxLoggerMiddleware.ts # 开发模式 Redux 状态变更日志
├── slices/                     # Redux Toolkit 切片
│   ├── commandSlice.ts         # 命令管理模块（替代 toolSlice）
│   ├── fileSlice.ts            # 文件管理模块
│   ├── imageSlice.ts           # 图片管理模块
│   ├── annotationSlice.ts      # 标注管理模块
│   ├── historySlice.ts         # 撤销/重做模块
│   ├── canvasSlice.ts          # 画布视图模块
│   └── styleSlice.ts           # 样式配置模块
├── selectors/                  # 组合选择器
└── serializers/                # 序列化器
    ├── markerFileSerializer.ts # 标记文件序列化器
    └── annotationSerializer.ts # 标注序列化器
```

### Slice 依赖关系

```text
fileSlice ──┬── 控制 imageSlice 的可用性（未打开文件时禁用图片操作）
            └── 控制 annotationSlice 的可用性

imageSlice ──┬── 决定 annotationSlice 的操作范围（按 activeImageId 过滤）
             ├── 决定 historySlice 的操作范围
             └── 决定 canvasSlice 的操作范围

commandSlice ─── 影响画布交互模式（创建 vs 编辑），管理命令执行状态

annotationSlice ──┴── 变更触发 historySlice 快照记录

styleSlice ──────── 全局样式配置，影响所有标注的渲染
```

## Slice 设计文档

### 1. commandSlice — 命令管理模块

#### 1.1 Slice 概述

**职责**：管理当前激活的工具类型，支持工具切换和重置，同时管理所有 MenuBar 命令的执行状态。

**核心功能**：

- 保存当前激活的工具类型
- 提供工具切换的 Action
- 支持工具状态的查询
- 管理命令的执行状态
- 记录命令的禁用状态

**支持的命令**：

| 命令 ID                      | 说明               | 快捷键       |
| ---------------------------- | ------------------ | ------------ |
| `file-new`                   | 新建标记文件       |              |
| `file-open`                  | 打开标记文件       |              |
| `file-save`                  | 保存标记文件       | Ctrl+S       |
| `file-save-as`               | 另存为标记文件     | Ctrl+Shift+S |
| `file-add-image`             | 添加图片           |              |
| `file-remove-image`          | 删除图片           |              |
| `file-export-png`            | 导出 PNG           |              |
| `edit-undo`                  | 撤销操作           | Ctrl+Z       |
| `edit-redo`                  | 重做操作           | Ctrl+Y       |
| `edit-clear-all`             | 清除所有标注       |              |
| `edit-delete-selected`       | 删除选中标注       | Delete       |
| `tool-horizontal-line`       | 选择水平线段工具   |              |
| `tool-vertical-line`         | 选择垂直线段工具   |              |
| `tool-normal-protractor`     | 选择普通量角器工具 |              |
| `tool-horizontal-protractor` | 选择水平量角器工具 |              |
| `tool-vertical-protractor`   | 选择垂直量角器工具 |              |
| `image-zoom-in`              | 放大画布           | Ctrl++       |
| `image-zoom-out`             | 缩小画布           | Ctrl+-       |
| `image-fit-window`           | 适应窗口           | Ctrl+0       |
| `image-actual-size`          | 实际大小           | Ctrl+1       |
| `image-rotate`               | 顺时针旋转         | Ctrl+R       |
| `image-rotate-counter`       | 逆时针旋转         | Ctrl+Shift+R |
| `image-reset-rotation`       | 重置旋转           | Ctrl+Shift+0 |

#### 1.2 State 结构

| 字段               | 类型/范围                | 说明                                                                     |
| ------------------ | ------------------------ | ------------------------------------------------------------------------ |
| `activeTool`       | 工具类型                 | 当前激活的工具；初始为无工具，也可为水平线段、垂直线段或三类量角器工具。 |
| `executingCommand` | 命令 ID 或空值           | 当前正在执行的命令；没有执行中的命令时为空值。                           |
| `commands`         | 命令 ID 到禁用状态的映射 | 记录各菜单命令是否禁用。                                                 |

#### 1.3 Actions

| Action                   | 类型        | Payload                                       | 说明                   |
| ------------------------ | ----------- | --------------------------------------------- | ---------------------- |
| `setActiveTool`          | 同步 Action | `toolType: ToolType`                          | 设置当前激活的工具     |
| `resetTool`              | 同步 Action | 无                                            | 重置工具为无工具状态   |
| `executeCommand`         | 同步 Action | `commandId: CommandId`                        | 开始执行命令           |
| `finishCommand`          | 同步 Action | 无                                            | 结束命令执行           |
| `setCommandDisabled`     | 同步 Action | `{ commandId: CommandId; disabled: boolean }` | 设置命令的禁用状态     |
| `setAllCommandsDisabled` | 同步 Action | `disabled: boolean`                           | 设置所有命令的禁用状态 |

#### 1.4 Selectors

| Selector                     | 返回值                              | 说明                                          |
| ---------------------------- | ----------------------------------- | --------------------------------------------- |
| `selectActiveTool`           | `ToolType`                          | 获取当前激活的工具类型                        |
| `selectExecutingCommand`     | `CommandId 或 null`                 | 获取正在执行的命令                            |
| `selectCommandDisabled`      | `(commandId: CommandId) => boolean` | 检查指定命令是否禁用                          |
| `selectIsToolActive`         | `(toolType: ToolType) => boolean`   | 检查指定工具是否激活                          |
| `selectIsCreatingAnnotation` | `boolean`                           | 是否处于标注创建模式（activeTool 不是无工具） |

### 2. fileSlice — 文件管理模块

#### 2.1 Slice 概述

**职责**：管理标记文件的操作，包括新建、打开、保存、另存为等功能。是应用的文件系统入口，负责协调业务状态与持久化存储。

**核心功能**：

- 管理当前打开的标记文件路径和状态
- 支持标记文件的新建、打开、保存、另存为操作
- 与 Electron 主进程通信，完成文件对话框交互
- 控制其他 slice 的可用性（未打开文件时禁用相关操作）

#### 2.2 State 结构

| 字段                | 类型             | 说明                                       |
| ------------------- | ---------------- | ------------------------------------------ |
| `filePath`          | `string \| null` | 当前文件的绝对路径；Untitled 文件为 `null` |
| `fileName`          | `string`         | 当前显示名称，如 `Untitled-1`              |
| `isUntitled`        | `boolean`        | 是否为尚未保存到磁盘的内存文件             |
| `hasUnsavedChanges` | `boolean`        | 是否有未保存的更改                         |

#### 2.3 Actions

| Action             | 类型        | Payload                                  | 说明                                      |
| ------------------ | ----------- | ---------------------------------------- | ----------------------------------------- |
| `createNewFile`    | 同步 Action | 无                                       | 创建内存中的 Untitled 文件，不写入磁盘    |
| `setFileOpened`    | 同步 Action | `{ filePath: string; fileName: string }` | 标记已保存/打开的文件                     |
| `setFileClosed`    | 同步 Action | 无                                       | 关闭当前文件并清理文件元数据              |
| `markFileSaved`    | 同步 Action | 无                                       | 标记文件已保存                            |
| `markFileUnsaved`  | 同步 Action | 无                                       | 标记文件有未保存的更改                    |
| `openFile`         | 异步 Thunk  | 无                                       | 打开文件并加载图片、标注内容              |
| `saveFile`         | 异步 Thunk  | 无                                       | 保存当前文件；Untitled 文件首次保存时弹框 |
| `saveFileAs`       | 异步 Thunk  | 无                                       | 另存为新文件                              |
| `exportImageAsPng` | 异步 Thunk  | `imageId: string`                        | 将指定图片及其标注内容导出为 PNG          |

同步 Action 只负责更新 `fileSlice` 的内存状态；异步 Thunk 负责与 Electron API 协作，并在文件操作成功或状态需要变化时触发对应的同步状态变化。用户取消文件对话框时，Thunk 应结束本次操作而不修改文件内容；文件读写或解析失败时，应返回失败状态供表现层提示用户。

##### 2.3.2 新建文件场景级时序图

新建文件采用 VS Code 的 Untitled 策略：只在 Redux 和内存中创建文件，不调用 `getTempDir()`，也不提前写入 `untitled.json`。文件首次保存时才弹出保存对话框并写入用户选择的路径。下图描述表现层到业务层的完整场景，和上面的 Action 级流程图互为补充。

```mermaid
sequenceDiagram
    participant U as 用户
    participant UI as 表现层(MenuBar)
```

**Untitled 文件策略**：

- `createNewFile()` 只创建内存中的 Untitled 文件，`filePath` 保持为 `null`。
- Untitled 文件使用递增显示名称（如 `Untitled-1`），不创建临时目录文件。
- 首次执行 `saveFile()` 时复用 `saveFileAs()`，由用户选择正式保存路径。
- 保存成功后将 `isUntitled` 设为 `false`，后续保存直接覆盖该路径。
- 新建或打开文件时清理图片、标注、历史、画布和命令状态，避免工作区数据串文件。

### 3. imageSlice — 图片管理模块

#### 3.1 Slice 概述

**职责**：管理多张图片的信息，支持图片的添加、切换和删除。

**核心功能**：

- 管理图片列表
- 管理当前激活的图片
- 支持图片的添加、删除和切换
- 保存图片的基本信息（路径、名称、尺寸等）

#### 3.2 State 结构

##### ImageState 顶层结构

| Key             | 类型                        | 默认值 | 说明                                     |
| --------------- | --------------------------- | ------ | ---------------------------------------- |
| `images`        | `Record<string, ImageInfo>` | `{}`   | 以图片 ID 为 key 的图片信息映射。        |
| `imageIds`      | `string[]`                  | `[]`   | 图片 ID 的有序列表，决定标签页展示顺序。 |
| `activeImageId` | `string \| null`            | `null` | 当前激活的图片 ID；无图片时为 `null`。   |

##### `images[imageId]` 的值类型：`ImageInfo`

```ts
interface ImageInfo {
  /** 图片唯一标识，应与 images 的映射 key 保持一致。 */
  id: string;
  /** 图片显示名称，用于标签页标题。 */
  name: string;
  /** 图片绝对路径，供画布加载图片资源。 */
  path: string;
  /** 图片原始宽度，单位为像素，必须大于 0。 */
  width: number;
  /** 图片原始高度，单位为像素，必须大于 0。 */
  height: number;
  /** 图片添加到标记文件的时间，使用 ISO 8601 格式。 */
  createdAt: string;
}
```

#### 3.3 Actions

| Action           | 类型        | Payload                                            | 说明                                                   |
| ---------------- | ----------- | -------------------------------------------------- | ------------------------------------------------------ |
| `addImage`       | 异步 Thunk  | 无（成功后生成 `ImageInfo`）                       | 调用图片选择对话框；用户选择后读取图片信息并写入 Store |

| `setActiveImage` | 同步 Action | `imageId: string`                                  | 设置当前激活的图片                                     |
| `updateImage`    | 同步 Action | `{ imageId: string; updates: Partial<ImageInfo> }` | 更新图片信息                                           |

### 4. annotationSlice — 标注管理模块

#### 4.1 Slice 概述

**职责**：管理所有图片的标注数据和选中状态，支持多种标注类型的创建、编辑、删除操作。

**核心功能**：

- 按图片 ID 组织标注数据
- 支持多种标注类型的创建
- 管理标注的选中状态
- 支持标注的编辑和删除
- 提供标注数据的查询
- 支持辅助线功能，显示标注间距离

**标注类型**：

| 标注类型   | 值                      | 说明                       |
| ---------- | ----------------------- | -------------------------- |
| 水平线段   | `horizontal-line`       | 标记水平位置，测量垂直比例 |
| 垂直线段   | `vertical-line`         | 标记垂直位置，测量水平比例 |
| 普通量角器 | `normal-protractor`     | 测量任意角度               |
| 水平量角器 | `horizontal-protractor` | 测量相对于水平线的角度     |
| 垂直量角器 | `vertical-protractor`   | 测量相对于垂直线的角度     |

创建流程：

1. 用户选择工具后进入标注创建模式。
2. PixiCanvas 创建标注创建会话实例。

### 5. historySlice — 撤销/重做模块

#### 5.1 Slice 概述

**职责**：实现撤销/重做功能，管理操作历史记录，支持多图片的历史管理。

**核心功能**：

- 按图片 ID 组织历史记录
- 记录标注操作的历史
- 支持撤销上一步操作
- 支持重做已撤销的操作
- 管理历史记录的大小限制（最多保存 20 次操作）

**设计原理**：

- 为每张图片维护独立的历史栈
- 使用两个栈（past 和 future）实现撤销/重做
- past 栈：保存已执行的操作，支持撤销
- future 栈：保存已撤销的操作，支持重做
- 每个历史条目是某时刻的标注状态快照

#### 5.2 State 结构

| 字段                       | 类型/范围                | 说明                                             |
| -------------------------- | ------------------------ | ------------------------------------------------ |
| `histories`                | 图片 ID 到图片历史的映射 | 每张图片独立维护 `past` 和 `future` 两个历史栈。 |
| `maxHistorySize`           | 数字                     | 历史记录上限，默认最多保存 20 次操作。           |
| `HistoryEntry.annotations` | 标注快照                 | 表示某一时刻指定图片的完整标注状态。             |

#### 5.3 Actions

| Action         | 类型        | Payload                                    | 说明                         |
| -------------- | ----------- | ------------------------------------------ | ---------------------------- |
| `pushHistory`  | 同步 Action | `{ imageId: string; entry: HistoryEntry }` | 推送新的历史条目             |
| `undo`         | 同步 Action | `imageId: string`                          | 撤销指定图片的上一步操作     |
| `redo`         | 同步 Action | `imageId: string`                          | 重做指定图片的上一步撤销操作 |
| `clearHistory` | 同步 Action | `imageId: string`                          | 清除指定图片的历史记录       |

#### 5.4 Selectors

| Selector              | 返回值                         | 说明             |
| --------------------- | ------------------------------ | ---------------- |
| `selectCanUndo`       | `(imageId: string) => boolean` | 检查是否可以撤销 |
| `selectCanRedo`       | `(imageId: string) => boolean` | 检查是否可以重做 |
| `selectHistoryLength` | `(imageId: string) => number`  | 获取历史长度     |

#### 5.6 历史记录中间件

标注操作需要自动记录历史，通过中间件实现。每次标注新增、更新、删除或全部清除完成后，业务逻辑层读取对应图片的最新标注快照，生成历史条目并提交 `pushHistory`。历史记录应与图片 ID 绑定，且不影响其他图片的历史栈。

### 6. canvasSlice — 画布视图模块

#### 6.1 Slice 概述

**职责**：管理画布的视图状态，包括缩放、旋转等，支持多图片的视图状态管理。

**核心功能**：

- 按图片 ID 组织画布状态

- 管理画布的旋转角度（范围：-180° - 180°）

## Store 配置

Store 负责组合 command、file、image、annotation、history、canvas 和 style 七个 Slice，并统一提供状态分发、订阅和开发日志能力。开发模式下可启用状态变更日志；序列化检查等运行时策略由 Store 配置统一管理。本节只描述职责和状态边界，不展开具体创建代码。

### RootState 类型

RootState 是 Store 的聚合状态，包含以下七个顶层状态域：command、file、image、annotation、history、canvas 和 style。各 Slice 只能通过公开的 Action 和 Selector 访问自身职责范围内的状态，跨 Slice 协作通过业务事件完成。

## 序列化模块（Serialization Module）

**职责**：负责标记文件和标注数据的序列化与反序列化操作，将业务数据转换为可存储的格式。

**核心功能**：

- 将标记文件对象序列化为 JSON 字符串
- 将 JSON 字符串反序列化为标记文件对象
- 将标注对象序列化为 JSON 格式
- 将 JSON 格式反序列化为标注对象

序列化模块只负责数据格式转换，不直接改变 Redux 状态。文件保存流程调用序列化模块生成持久化内容，文件打开流程调用反序列化模块并在校验通过后更新 fileSlice、imageSlice 和 annotationSlice。解析失败时保持当前工作区状态不变，并将失败结果交由表现层提示。
